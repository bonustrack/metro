# Organization models and the model gateway (`packages/inference`, `apps/daemon/src/gateway/`, `docs/ORG-MODELS.md`, next: `docs/GATEWAY-SERVER.md`)

Moved out of `CLAUDE.md` on 2026-11-10 to keep that file short. These rules bind exactly like `CLAUDE.md`: read this file before changing anything in this area, and keep it up to date with the code.

- **Where the setup lives** (Less, 2026-10-15): the providers, their keys and sign-ins, and the model order belong to the organization in api.metro.box's Postgres (`model_connections`, `model_routes`, `model_hosts`), like connectors. The gateway stays on each box, and every request goes from the box straight to the provider; metro.box never relays a model request. Providers: OpenRouter, Routeway (2026-10-17), Codex (both sign-ins), Anthropic with an API key or a Claude subscription, Amazon Bedrock. **Gemini is gone.** **A Claude subscription is an organization connection like the others** (2026-10-16, owner's call; before, Claude logins lived on each box, see Removed). Each agent uses the organization's default route unless an organization admin sets an override for that agent. The organization's Gateway page (`#/organization/models`) holds the connections and the default; the agent's Gateway page shows the effective route with the box's usage and lets an admin set or clear the override.
- **A route is `{primary: {connection, model}, fallbacks: [{connection, model}], helpers?: {primary, fallbacks}, effort?: {main?, helpers?}}`**, 8 fallbacks at most (helpers too). `connection` is a `model_connections.id` of the same owner; a `local:` step (a box Claude login before 2026-10-16) is refused with a sentence that points to the Claude subscription, and a stored one is dropped on read. Every step names a model. **No route at all (no override and no default) means no model**: the gateway answers 503 and the session does not start. **A route always has a primary** (`PUT /api/models/route` refuses one without it): deleting a connection removes it from every route of its owner, the first remaining fallback replaces a primary that pointed at it, and a route left with nothing is deleted (its helpers and effort with it); the helper chain loses the connection the same way, and helpers left with nothing use the main models again. Every read of a route or connection for an agent also matches the agent's current owner.
- **Effort and helpers belong to the route** (Less, 2026-10-18: "set the effort from the model setup", "setup model for the main session and different for the sub agent / workers"): `effort.main` and `effort.helpers` are each `low`, `medium`, `high`, `max` or `asked` (As the agent asks: Metro leaves the effort as Claude Code sent it; `EFFORT_LEVELS`, `EFFORT_DEFAULTS` and `readEffort` in `@metro-labs/core/effort`), absent meaning the default (`low`, `max`); `helpers` is a second model order for helpers, absent meaning helpers use the main one. Both live in the `model_routes.route` JSON (no migration); a part Metro cannot read is dropped on read, never the route. **`PUT /api/models/route` keeps the stored `helpers` or `effort` when the body leaves it out, and `null` clears it** (strict 400 by name for a bad value), so a page that does not know them never wipes them; the page sends both on every save. A box before this release ignores both and keeps the defaults.
- **One sealed secret per connection** (`METRO_CONNECTORS_KEY`, `packages/connectors/src/secrets.ts`, additional data `metro-model/v1\n<owner>\n<connection id>`, so a connector's value never opens as a model secret and the reverse): `{kind: 'key', apiKey}` for Anthropic, OpenRouter, Bedrock and Routeway, `{kind: 'claude', token}` for an Anthropic Claude subscription (the token `claude setup-token` prints: `sk-ant-oat01-` then 32 to 512 of `[A-Za-z0-9_-]`, `isClaudeToken` in `@metro-labs/core/claude-token`; about a year, no refresh; marked `detail.subscription: true` with `signedInAt`). **A token is checked before it is kept** (`checkClaudeToken` in `apps/api/src/models/provider-lists.ts`, on `POST /api/models` and `PATCH … {claudeToken}`): one free `POST /v1/messages/count_tokens` (`claude-haiku-4-5`, one word) with `Authorization: Bearer <token>` and the `oauth-2025-04-20` beta; a 401 or 403 is a 400 `Anthropic refused this token, so it was not saved…`, and any other answer or no answer is a 503 `Metro could not check this token…`, so nothing unverified is saved, `{kind: 'codex', method, accessToken, refreshToken, expiresAt, clientId?, subject?, accountId?}` for Codex. **A refresh token never leaves api.metro.box**: Codex tokens are refreshed only there, single flight per connection under a row lock, when a delivery finds `expiresAt` within 5 minutes or on a forced refresh, **but never a forced one within 60 s of the last token** (`detail.refreshedAt` or `signedInAt`; it answers the current connection, so a provider that keeps refusing a token cannot make every request refresh); a refused refresh marks the connection signed out (`detail.signedOut`) and delivery omits its credential. No API answers a secret to the page. **A Routeway key is checked before it is kept too** (`checkRoutewayKey` in `apps/api/src/models/routeway.ts`, on `POST /api/models` and on a new key): one free `POST https://api.routeway.ai/v1/messages/count_tokens` with `x-api-key`; a JSON 401 or 403 is a 400 `Routeway refused this key…`; any other JSON 4xx but 429 keeps the key, since Routeway reads the key before the request (a bad key with an empty body gets 401, measured 2026-10-17); a 429, a 5xx, a web page (Cloudflare's challenge, which an unknown path or a request with no key gets) or no answer is a 503 `Metro could not check this key…`.
- **Delivery to the box** (`gateway/org-models.ts`): `POST /api/agents/models` (signed `MetroAgent`, never from a browser) answers the effective `route` (with its `helpers` and `effort` when set), its `source` (`agent`, `organization` or null), only the connections that route names (the helper chain's included), each with its `auth` kind (`key`, `subscription`, `codex`) and `signedOut` but **no credential since phase 4 of `docs/GATEWAY-SERVER.md`** (`credential: null` on every connection, `factsOnly` in `apps/api/src/models/agent-api.ts`; gateway.metro.box opens the credentials itself, and a box from beta.323 needs none), and the organization's `chatgptHostId`. The delivery still renews a Codex token near its end (the shared `agentModelsOf`), answering without the token. `POST /api/agents/models/refresh` is gone (beta.324): no box routes, and gateway.metro.box renews with `refreshModelConnection` itself. The box keeps it in memory only: fetched at boot, every 60 s and on `POST /api/model/sync` (member; the page calls it after every change). **Only a 401 with code `agent_key_missing` clears it** (the key is unknown, or its agent was deleted, unenrolled or moved: the one answer api.metro.box gives for that); every other failure keeps the last good copy with no expiry, any other 4xx included (a clock or replayed-nonce 401, a nonce budget 429, a proxy's 403 or 429 page, a 404 or 400 during a rollback). The page's sync fetches at most once per 5 s; a call inside the window answers what the box holds and one fetch follows at its end. **Without an enrolled agent key there is no organization setup**, so no model: the gateway answers 503 and the session does not start. The box routes nothing itself (beta.324): the copy serves its session start, its Model API, the agent view and the live switch. When the effective primary model changes, the daemon sends the live switch (see The Agent SDK runner).
- **Metro's own `model.json` is gone** (2026-10-16): at start `removeModelLeftovers` (`gateway/model-leftovers.ts`, the style of `connectors/leftovers.ts`: exact names, regular files only by `lstat`, never fatal, one info line with the count) deletes what the old model setup wrote in `<agents dir>`: `model.json` (version 2 or 3) and `chatgpt-host.json` (the box's ChatGPT host id for the old Codex sign-in), each with its `.tmp-<pid>` file, and the agent's `~/.metro/claude-logins` folder of the old box Claude logins (as the agent, `removeHome`; left alone when the agent user is expected but missing). **The agent view still writes `<agent home>/.metro/agents/model.json` as `{route, connections: [{id, provider, model}]}`** from the effective route (the primary connection's id and the route's model), so `currentModel` in `packages/cli` is unchanged.
- **The box's Model API is read-only apart from sync**: `GET /api/model` and `GET /api/model/snapshot` answer the same `{source, sync: {enrolled, at, error}, route: <primary connection id or ''>, model: <primary model>, fallbacks, ready, reason, connections, chain, helpers, effort}` (no `usage` or `lastServed` since beta.324, and `chain` names no hold but a signed-out account or a missing model or region (`chainStatus` with `setupNotReady`; beta.324 judged it by the credentials the box no longer gets, so every Codex row read `Skipped: Codex is not signed in` while the gateway used it): the box routes nothing, and the page merges the windows from api.metro.box, see Usage windows) (`helpers` is null or `{route, model, fallbacks, chain}` for the helper chain; `effort` is the two levels applied, defaults filled in; a box before 2026-10-18 answers neither, and the agent's Gateway page then asks to update Metro when the route sets them), where `connections` holds only what the route names, each with `hasKey` and `subscription` and never a secret, and no route answers `ready: false` with a reason naming the Gateway page; `POST /api/model/sync` (member) fetches now and answers the same body. An unenrolled box answers `sync.enrolled: false`, and the page enrolls it by itself (see The app). The add, save, choose, drop, fallbacks, bundle and restore routes, the box's Codex and OpenRouter sign-ins, the box's provider model lists and the Claude login routes are gone. The page reads only this answer: `route` is the primary's id (`''` for none), an older box's `usage` is keyed by connection id, and the answer of a daemon before beta.309 is not read.
- **The box relays its model requests to gateway.metro.box** (`gateway/relay.ts`, phase 3 of `docs/GATEWAY-SERVER.md`, from the release after beta.321): `/gateway/v1/messages`, `/count_tokens` and `GET /v1/models` go up with the box's MCP token as `Authorization: Bearer` (the agent key, `x-api-key` and Claude Code's own `authorization` never leave the box), the hint headers and the body as they came, and the answer streams back through the router's `pipeResponse` and idle watch. No token yet is a 503 saying the agent is not linked; a 401 from the gateway is a 503 and registers the token again (`reregisterMcpToken`); an unreachable gateway is a 502; Claude Code retries all three. `METRO_GATEWAY_URL` names the gateway (default `https://gateway.metro.box`, same rules as `METRO_MCP_SERVER_URL`); empty means no gateway: every model request is a 503 that says so (`boxGatewayHandler` in `relay.ts`; beta.324 removed the box's own router, its usage probes and the Codex refresh). The page reads usage and windows from api.metro.box. **A relaying box needs no credential** (beta.323): its session start and Model API judge readiness with `setupNotReady` (`setupNotReady` in `model-config.ts`: a model id, a Bedrock region, an account not signed out), and the delivery's per-connection `auth` (`key`, `subscription`, `codex`) and `signedOut` give the Model API its `hasKey`, `subscription` and `signedOut` without a secret (`deliveredConnection` prefers them; an older api without them reads as before). Step 2 of phase 4 (api.metro.box sends no credential to boxes, #394) shipped once every box ran beta.323, since a beta.322 box judged readiness from the credentials.
- Claude Code on the box talks to `/gateway`; auth is the agent key in `x-metro-key`, never `Authorization` (that holds Claude Code's own login or the agent key standing in for one, and never reaches a provider).
- **The Anthropic route is verbatim apart from the credential** (path, query, headers except hop-by-hop, `accept-encoding`, `x-metro-key`; body bytes as received). Re-serialize only when metro changed something. An API key swaps `authorization` for `x-api-key` and drops OAuth betas; a Claude subscription replaces `authorization` with `Bearer <token>`, drops `x-api-key` and adds the `oauth-2025-04-20` beta (`loginHeaders` in `forward.ts`); small (haiku) models pass through unpinned.
- **Routeway (https://routeway.ai; Less, 2026-10-17: "a bit like OpenRouter, with different models") is an Anthropic-compatible route** (`toRouteway` in `gateway.ts`, `gateway/routeway.ts`): `https://api.routeway.ai` plus the request's own path and query (`/v1/messages`, `/v1/messages/count_tokens`), the body as Claude Code wrote it apart from the routed model (`routeway:<id>`, whatever model the request names; an id may hold a colon, `deepseek-v4-flash:free`) and the effort policy, the headers of an Anthropic API key (`x-api-key`; the client's `authorization`, `x-metro-key` and OAuth betas dropped; `anthropic-version` and the other betas kept; a `metro` user agent when the client sent none), and never the Anthropic thinking binding. **A tool whose `input_schema` has no `properties` gets an empty `properties: {}`** (`routewayTools`): Routeway answers 422 `Field required` for `tools.N.input_schema.properties`, and Claude Code sends `{type: 'object'}` alone for a tool without arguments, so Chen answered once and then every turn failed (2026-10-18). **A list of types (`"type": ["integer", "null"]`) becomes `anyOf` of single types at every depth** (a one-item list becomes that type; with an existing `anyOf` both go under `allOf`): Routeway takes one type per field (422 `Input should be 'string', 'number', …`). A body with nothing to fit is still sent byte for byte. A JSON refusal from Routeway is logged as `gateway: Routeway refused the request` with its `reason` and `param` (300 characters at most each), never the request. A shape Routeway refuses (400) is sent again as Claude Code wrote it, streams get 25 s pings, a 401 is relayed as 403, and a 402 or 429 hands the request to the next model like every provider. A web page instead of the API (Cloudflare's challenge) is a 502 `api_error`, never relayed as a refused key, except a 402 or 429 page, which still hands over. **A box before beta.312 does not know `routeway`**: it drops that connection from the delivery, and when Routeway is the main model it had no route at all, so update every box before choosing Routeway as a main model. From beta.312 a main model whose connection was not delivered (a provider the box does not know) gives way to the first backup that was (`primaryRoute` in `model-config.ts`). Routeway's usage and balance calls need a management key, which Metro does not ask for, so usage is the token tally of real answers and the page says `Usage shows on routeway.ai` with a link to https://routeway.ai/dashboard.
- **MCP tool search: metro does the API's part for every route, Anthropic included** (`fitToolSearch` in `gateway/tool-search.ts`), so there is one mechanism and no tool search beta upstream. `ToolSearch` is a client-side tool of Claude Code, not an API server tool: Claude Code runs the search over its own deferred list (`query`: `select:A,B` or keywords, `max_results`) and answers with a `tool_result` of `tool_reference` blocks plus a `Tool loaded.` text (`No matching deferred tools found` when nothing matches). It sends only the deferred tools found so far (`defer_loading: true`) and a `DeferredToolPlaceholder`, and names the other deferred tools in a system reminder. Metro drops the placeholder, shows a deferred tool only once a reference or a `tool_addition` in the request's own history found it (until a `tool_removal`), sends it without `defer_loading`, and turns each reference into the `<functions>` block the API would show (one `<function>{"description","name","parameters"}</function>` line per tool, as ToolSearch's own description promises; `No matching deferred tools found` when none is sent). `tool_addition` (by reference, or by `tool_definition`, which metro also declares in `tools`) and `tool_removal` blocks in a `role: system` message, which Claude Code uses when a request has no ToolSearch, become the same block or a `Tool <name> is no longer available.` line. A cache breakpoint on a replaced block moves to its replacement. The betas `advanced-tool-use-`, `tool-search-tool-` and `mid-conversation-tool-changes-` are dropped. It is stateless: each request is fitted from its own tools and history. A body with nothing deferred and no reference passes byte for byte (the betas still leave the header), and the 400 retry keeps the fit. The cost: a found tool changes the tools list, so a provider's prompt cache is written again once per discovery (Anthropic's native tool search kept it), and a found schema is in context twice (the tools list and the search result).
- **Effort policy** (`gateway/effort.ts`): the route's `effort` per thread (`plannedEffort`), by default main thread `low`, subagents `max`; `asked` leaves the request as sent; chores untouched; Routeway gets it as Anthropic does, Codex maps `max` to `xhigh`. Subagents are detected by `x-claude-code-agent-id` or `cc_is_subagent=true`. **A compaction always runs at `low`, on every thread and every provider, whatever the route sets** (`requestKind` answers `compact`, `COMPACT_EFFORT`; `asked` does not raise it either): Claude Code's summary request is told apart by `x-claude-code-request-class: compaction` or by its prompt, a text that starts `CRITICAL: Respond with TEXT ONLY. Do NOT call any tools.` in the last user message (`compactionRequest`). Measured 2026-10-23 on 2.1.287 against a stand-in upstream (a manual `/compact` and a worker's automatic one): a compaction is an ordinary request of the thread (its own system prompt, tools, thinking and effort, a worker's agent id) whose last user message ends with that prompt; the bundled code builds the reactive one the same way, and the retry after a first try with no text uses the system prompt `You are a helpful AI assistant tasked with summarizing conversations.` with the same prompt. A worker's compaction stays on the worker models (`helperRequest` picks the lane). Why: on Lisa's Codex route a worker at `max` (`xhigh`) took 9 to 12.6 minutes per compaction (2026-10-23). Lowering only ever keeps the thinking settings valid; on Anthropic a worker's compaction loses its messages cache, since an effort change invalidates it. Only an effort the client sent is replaced, **the top-level `output_config.effort` and every per-turn one on a `messages[]` entry**: Claude Code puts one on each mid-conversation system message, and the model follows that one. OpenRouter caps at `high`. Anything metro reshaped is retried once as the client sent it on a 400.
- Disabled thinking is dropped for models that cannot run without it (`withThinkingFor`) and on OpenRouter. The known ones are a pattern in `gateway/effort.ts`; any other model whose 400 says `"thinking.type.disabled" is not supported` is learned for the daemon's life and the request goes again without the setting (`refusedThinkingOff` in `gateway.ts`; Claude Sonnet 5.5, 2026-09-29). Thinking blocks that no longer match are dropped via `block_binding` on the Anthropic route.
- **A provider refusing the stored credential is relayed as 403, never 401** (a 401 makes Claude Code discard its own login).
- **An Anthropic step uses its connection's API key or its Claude subscription token, never a login the request carries.** A token Anthropic refuses (401) hands the request to the next model of the chain like a 402 or 429 (`SubscriptionRefused` in `forward.ts`, `heldAttempt` in `gateway.ts`; the step rests 60 s with the hold `token refused, sign in again`, logged), and only when it is the last model is it answered 403 `Anthropic refused the Claude subscription <label>: sign in again on the Gateway page`, never 401: the token has no refresh, so a new token (`PATCH /api/models/<id> {claudeToken}`, a new revision) is the fix. No route is a 503 that names the Gateway page, so Claude Code retries it while a first sync is still on its way.
- Every provider stream has an idle deadline (`METRO_GATEWAY_IDLE_MS`, 5 min) and non-Anthropic routes get 25 s pings.
- **An image in a tool result reaches Codex as an image** (`resultImages` in `gateway/text.ts`): `function_call_output.output` is an `input_text`/`input_image` array in the result's own order, as the Codex CLI sends it (`FunctionCallOutputPayload` in `openai/codex`). Claude Code's Read returns images this way, so before this an agent on Astra was told "this model cannot see it" (2026-09-30). An image metro cannot forward (not base64, empty) still leaves that note.
- Codex goes through `gateway/codex.ts` (`reach`: a 401 gets one central refresh and one retry) and `gateway/subscription.ts` (`relayTranslated`, `answerWhole`). Every non-Anthropic stream shares `relayFrames` in `forward.ts` (pings, usage scanner, idle deadline).
- **A provider failure is logged once, with the connection label, the model, the provider's code and its message (300 characters at most), never the request** (`noteFailure` in `gateway/failures.ts`). Codex: `gateway: Codex did not complete the response` for `response.failed`, a stream `error`, a `response.incomplete` other than `max_output_tokens` (the reason as the code), and a stream that ends or goes quiet before it completes, streamed or whole (`report` of `CodexEventTranslator`); `gateway: Codex refused the request`, with its `status`, for a refusal before the stream. The Anthropic-shaped routes (Anthropic, Routeway, OpenRouter through `pipeResponse`, Bedrock's stream exceptions) log an `error` event in the middle of a stream as `gateway: the provider sent an error in the middle of its stream` (`StreamErrors`); the stream itself is relayed as it came. Before 2026-10-23 none of this was logged, so a compaction that failed with "Server error mid-response" left only `gateway: routing` lines.
- **Each Codex thread has its own prompt cache key** (`threadKey` in `codex.ts`, `prompt_cache_key`, and the ChatGPT backend's `session-id` header): the main thread keeps Claude Code's `x-claude-code-session-id`, and a worker gets the SHA-256 (base64url) of that session id and its `x-claude-code-agent-id`. Claude Code sends the parent's session id on every worker request (measured on 2.1.287), so before 2026-10-23 the main thread and every worker shared one key, which OpenAI's guide counts per key against about 15 requests a minute on models before GPT-5.6. Consecutive requests of one thread are append-only in the Responses shape (same instructions, tools and reasoning, the earlier input a prefix of the later; `test/codex-cache.test.ts`), so the cache can hold everything but the newest turn; a found tool still changes `tools`. Why Lisa's worker read only 0 or 6,528 cached tokens a turn is not proven offline (see `docs/HISTORY.md`, 2026-10-23).
- **Codex signs in two ways, on api.metro.box, and each connection keeps which one it used** (`detail.method`; Less, 2026-10-04 20:20Z: "I think we should have all the options possible, the one with code was more clean, we should have that option too"). The organization's Gateway page offers **Continue with ChatGPT** first (the default, OpenAI's official route) and **Sign in with a code** below it, with the note "Uses the Codex app's sign-in (not in OpenAI's docs for other apps)." Signing a connection in again, either way, updates it in place with a new revision (its id and every route that names it stay). Routes: `POST /api/models/codex/login {connection?}` answers `{authorizeUrl}`, `POST /api/models/codex/callback {url}` finishes it, `POST /api/models/codex/device {connection?}` and `GET /api/models/codex/device/<id>` run the code sign-in.
- **Continue with ChatGPT is OpenAI's official Sign in with ChatGPT for open-source apps** (`method: 'chatgpt'`; Less, 2026-10-04: "Ok lets try implement that instead of our complex flex"; https://developers.openai.com/siwc/token-sharing-open-source): a ChatGPT Plus or Pro plan, through the public Responses API. The first sign-in of a connection registers Metro at `https://auth.openai.com/api/accounts/authorize` with `client_id=dynamic_agent_client`, `agent_name_hint=Metro`, the organization's `ext_agent_host_id` (`model_hosts.chatgpt_host_id`, `urn:uuid:…`, made once per organization), scope `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`, state, nonce and PKCE S256. The redirect must be `http://127.0.0.1:1455/auth/callback` (OpenAI's loopback rule), which lands on the person's own computer, so the page asks them to paste that address. The issued client (`oaiapp_…`) is kept with the connection and reused, with the email as `login_hint`, when that connection signs in again this way. **The page warns before the tab opens** that ChatGPT ends on a 127.0.0.1 page that does not load and to copy that address back, and the paste box finishes by itself as soon as the text holds `code=` and `state=` (`carriesCodeAndState` in the client, the `ready` prop of `PasteAddress`). The access token lasts an hour. A sign-in counts only when the granted scope holds `chatgpt.tokens.use.direct` and the ID token's `iss`, `aud` (the client), `nonce` and `sub` match. Requests go from the box to `https://api.openai.com/v1/responses` with `Authorization: Bearer` only (no `originator`, `chatgpt-account-id` or Codex user agent), `store: false`, `stream: true`, and none of the fields OpenAI rejects on this route. A `subscription_sharing_usage_limit_exceeded` refusal is a 429 `rate_limit_error` that names https://chatgpt.com/settings/usage, whether it comes before the stream or as `response.failed`. OpenAI allows this plan usage for open-source and locally hosted apps; a paid or remotely hosted app must send its interest form first (https://openai.com/form/sign-in-with-chatgpt-interest/).
- **Sign in with a code is the Codex app's own device-code login** (`method: 'code'`, from `codex-rs/login/src/device_code_auth.rs`; unofficial for other apps, so OpenAI can change or refuse it at any time): a code from `https://auth.openai.com/api/accounts/deviceauth/usercode` with the Codex CLI's client `app_EMoamEEZ73f0CkXaXp7hrann`, typed at `https://auth.openai.com/codex/device`, while the page polls. The ChatGPT account id and plan come from the ID token's `https://api.openai.com/auth` claim. **Only these connections use the ChatGPT backend**: `https://chatgpt.com/backend-api/codex/responses` with `chatgpt-account-id`, `originator: codex_cli_rs`, a `codex_cli_rs/<version> (<os> <release>; <arch>) metro` user agent, `openai-beta: responses=experimental` and `session-id`, since the backend hides models newer than the version a client announces. The version is the latest `@openai/codex` on npm, read at most every 6 hours (`codex-version.ts`, 0.157.1 when npm does not answer; `METRO_CODEX_VERSION` overrides it, `METRO_CODEX_REGISTRY` points tests elsewhere). The `~/.codex/auth.json` import and the `wham/usage` probe stay removed.
- **OpenRouter signs in on api.metro.box too**: `POST /api/models/openrouter/login {connection?}` answers `{authorizeUrl}` with the callback `https://api.metro.box/api/models/openrouter/callback` (open, single-use state), which stores the key and sends the browser back to the page. A key can also be pasted.
- **Usage windows come from real answers and from free probes, on gateway.metro.box** (the box's own probes, `usage-refresh`, went in beta.324; Less, 2026-10-26: "see OpenRouter credits bar, but also ChatGPT / Claude sub usage bars"). The router reads the headers of real answers and real 429s. On top, gateway.metro.box asks every account of the setups it loads, at once and then at most every 5 minutes, for as long as a setup named it in the last hour (`UsageProbes` in `apps/gateway/src/usage-probes.ts`, fed by `Setups`; `probeUsage` in `packages/inference/src/probes.ts`; one warning per account until it answers again). **OpenRouter**: `GET /api/v1/key`, the key's limit and spend, as the `Credits` window (`/api/v1/credits` needs a management key). **ChatGPT signed in with a code**: `GET https://chatgpt.com/backend-api/wham/usage`, the Codex app's own call (unofficial, like that sign-in), for the plan's windows, credits and wall (`chatgptUsage`). **Continue with ChatGPT**: OpenAI documents no usage call, so none is made; its windows come only from `x-codex-*` headers when an answer carries them, and the page links to https://chatgpt.com/settings/usage. **A Claude subscription**: its token carries the inference scope only, so there is no usage call; the probe is a free `POST /v1/messages/count_tokens` read for the `anthropic-ratelimit-unified-*` headers, which change nothing when Anthropic does not send them there (not verified with a real token yet). An Anthropic API key, Bedrock and Routeway are not asked. Probe results are merged per window with the header ones (`mergeUsage`), shared between machines and read by the page like them (`windows.ts`, `GET /api/models/windows`), and count for the holds. The page shows the account each connection signed in with next to its model (`account`).
- **Fallback models** (`gateway/fallback.ts`, the route's `fallbacks`; Less, 2026-10-03: "select fallbacks models, and make it possible to set the order. A model should stop once it reach more than 95% usage. We should check for usage without sending a request that spend usage"). Each request walks the route's primary, then the fallbacks in order (`chainOf`; one not set up, or the same as an earlier one, is left out; a haiku chore stays haiku on a Claude fallback; `deliveredOf` drops a step with no model) and skips one that is held (`holdOf`): a usage window above 95% that has not reset yet (unscoped windows count for every model of the connection, `Weekly, <Name>` only for a model id holding that word, `Tokens per minute` never), or a 402 or 429 it answered (or a 401 on a Claude subscription), until its `retry-after`, its unified reset, or 60 s. When every model is held, the first one is tried. A 402 or 429 from a model that has a next one is held back from Claude Code (`holdLimitRefusal` in `forward.ts` swallows that `writeHead` and its body) and the same request goes to the next model; the last model's refusal is relayed as it came. Nothing is retried once a stream has started. The choice is made per request, so the agent is back on its first model as soon as the window resets, with no session restart; a change of model and a 429 hand-over are logged. **Usage stays free**: a hold comes from the headers of real answers, a real 429, or a free probe on gateway.metro.box (above), never from a request that spends usage. Anthropic's header windows are merged per window, newest first (`mergeUsage`). `GET /api/model` carries `chain` (each model with its usage, what holds it and which one is `active`).
- **Helpers walk their own chain** (`chosenChain` in `gateway.ts`, `helperSetup` and `pinnedRoute` in `model-config.ts`): when the route has `helpers`, a subagent request (the effort policy's detection) walks the helper primary and fallbacks with the same holds and hand-over; the main thread keeps the main chain, and without `helpers` everything is as before. **On the helper chain the step's model always wins**, whatever model id the worker sent (it asks for the main model, `<provider>:<model>` included, which the main chain's provider defaults would keep), so nothing escapes to the main chain; only a haiku chore on a Claude step passes as asked. Holds are per model on both chains; the choice log carries the lane (`main`, `helpers`). `test/helpers-route.test.ts` checks every provider.
- **Every model list the page shows is the provider's own, kept an hour**, so a new model shows up without a Metro release (Less, 2026-09-29, Sonnet 5.5 missing from the picker). **An organization connection's list comes from api.metro.box** (`GET /api/models/<id>/models` with the stored credential, `{models: [{id, name, price?}]}`, kept one hour per connection; OpenRouter lists only models that take tools and answer text; Anthropic and Bedrock come newest first). **A Claude subscription's list** asks Anthropic's `/v1/models` with `Authorization: Bearer <token>` and the `oauth-2025-04-20` beta, and offers the known Claude models (`KNOWN_CLAUDE` in `apps/api/src/models/provider-lists.ts`, worth extending when Anthropic ships a model) when Anthropic refuses; a refusal is not kept, so the next look asks again. **Routeway's list is public** (`routewayModels` in `apps/api/src/models/routeway.ts`: `GET https://api.routeway.ai/v1/models`, no key, kept one hour for every Routeway connection): only the models that are `available`, list `/v1/messages` in `endpoints` and `tools` in `supported_parameters` (140 of 290 on 2026-10-17), newest first by `created`, named by `short_name`, with `price` per token from `pricing.input` and `pricing.output` `price_per_million_t` and `context` from `context_length`, which the picker shows after the price (`1M context`, `contextLabel` in the client's `model-options.ts`). A web page or a broken answer is a 503, never a key refusal.
