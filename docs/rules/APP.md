# The app (`apps/app`, `packages/client`)

Moved out of `CLAUDE.md` on 2026-11-10 to keep that file short. These rules bind exactly like `CLAUDE.md`: read this file before changing anything in this area, and keep it up to date with the code.

- **One Expo app for metro.box and the phones, like Stage** (Less, 2026-10-04: "only 1 code for both the mobile app and the web app"): Expo SDK 57, React Native 0.86, Expo Router, react-native-web, `@stage-labs/kit` for every screen. The web is the Expo web export (`bun run build`, the root `netlify.toml`); Android and iOS run the same code in a dev client. A platform file (`*.web.tsx`, `*.web.ts`) only where the web and the phone must differ: the terminal (DOM and CSS on the web, a link to metro.box on the phone), storage, file save and pick, the picture picker, the document title, the transcript scroll.
- **`packages/client` (`@metro-labs/client`) holds everything without React**: the api.metro.box and box clients (`api/`), sign-in and the route grammar (`auth/`, `route.ts`, `selection.ts`), the `.metro` format (`export/`). It reaches the platform only through `platform.ts` (`configurePlatform`): `kv` and `tabKv` storage, `location` (the current hash, replace, push), `apiBase`, the sign-in return url and `random`. The web keeps the browser defaults; the phone keeps the account in SecureStore and the rest in AsyncStorage, read once before the first screen (`lib/storage.ts`). Its tests live in `packages/client/test`; the compat probe imports it.
- **Hash addresses are unchanged**: `#/<org slug or id>/<agent slug or id>/<page>`; `#/settings`, `#/login`, `#/auth/<code>`, `#/admin…` are global. Stage's expo-router patch (`patches/expo-router@57.0.23.patch`) makes Expo Router read and write `/#/...` on the web. **The whole app renders from the root layout** (`app/_layout.tsx` renders `Screen`; `app/index.tsx` and `app/[...path].tsx` render nothing), so the query cache and the sign-in survive every navigation; the route is parsed with the client's `routeSelection` (`lib/route-hash.ts`). A first segment with a dot or colon is a box host (the link a daemon prints): `HostRedirect` (`components/gates.tsx`) asks the box's `/api/mode` for its owner and rewrites the link to the owner organization's agent (`hostTarget` in `auth/host-link.ts`), adds it there only when that organization does not list it yet, and refuses a box whose owner is an organization the account is not in; with no owner known it prefers the selected organization's listing, then any other. A bare slug is never a box address.
- **A navigable thing is a `RouteLink`** (or `TextLink`): an expo-router `Link` with `asChild`, so the web gets a real `<a href="/#/...">` and modified clicks open a new tab. **The child's style must be flat** (`StyleSheet.flatten`): expo-router's Slot spreads a style array into the DOM `style` and the page goes blank ("Failed to set an indexed property [0] on CSSStyleDeclaration"). **A click must go through the router, never the browser following the href**: on the web the `Link` hands its handler to the child as `onClick`, which react-native-web's `Pressable` replaces with its own, so `RouteLink`'s child (`LinkPress`) passes it on as `onPress` (`test/route-link.test.ts`). Without that the browser followed the href, React Navigation answered the `popstate` with a new root state, the root layout remounted with a fresh QueryClient, and every rail or list click loaded the whole app again (2026-10-16).
- **The shell is a rail, a list and a detail on a wide screen, and a floating tab bar on a phone** (the v2 redesign, 2026-10-16, see `docs/HISTORY.md`; `components/shell/`). Four sections, in this order: **Agents, Connectors, Models, Organization** (`SHELL_SECTIONS` in `lib/shell-sections.ts`), with the icons robot, plug, processor and buildings (`components/shell/section-icons.ts`; Models had a sparkle until 2026-10-17, and its empty and refusal states use the processor too). Wide (`AppShell.tsx`): the `Rail` (icons only with tooltips, the organization's avatar and switcher at the top, Jump and the account menu at the bottom), a 320 px `ListPane` (the agents, the connectors, or Default route then the accounts; Organization is one page with Profile, Members, Invites and AWS accounts) and the detail pane. **The detail pane fills the space next to the list** (v3, 2026-10-17): content left-aligned with 40 px padding (`PAGE_PAD`), 32 px at the top (`PAGE_TOP`), at most 1200 px wide (`WIDE_WIDTH`), never a centred column; `AppShell`'s `fluid` lifts the cap (the operator's tables). Inside a page (`components/ui/Layout.tsx`): `Readable` (at most 680 px, `READABLE_WIDTH`) for text and forms, `Wide` (up to 1200 px) for tables, tool lists, logs and the run timeline, `WithRail` for a 280 px right rail of `Fact`s next to the main column (stacked under it on a phone; agent Home shows Model, Channels and Server there). A `Group` is readable by default. Phone: each section is a tab root with a large title (`TabRoot`), a row pushes the detail, and the floating pill `TabBar` (icons, the active one labelled) stays at the bottom. **The rail shows an Admin item (shield) for the operator only** (`isOperator`, above Jump), and on the phone the Organization tab's Your account group has an Admin row; both open the operator's `#/admin…` pages in the same shell (see The operator's admin area); the old sidebar frame and its drawer are gone. **The web scrolls the document, the phone a ScrollView** (`PageScroll`, like Stage's ScreenScroll): no `overflow: scroll` boxes or `100vh` on a page; the list pane is sticky on the web. Scroll views are the kit `Scroll`, which hides the scroll indicators on phones, and touch screens hide the web scrollbars (`pointer: coarse` in `public/index.html`), like Stage. Menus anchor under their trigger on a wide web screen and are a bottom sheet (`DropdownMenuSheet`) on narrow screens and phones.
